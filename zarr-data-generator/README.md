# Zarr test data generator

The fixtures under `../images/zarr` are generated by a pinned zarr-python reference implementation. The generator is
self-contained: [`uv`](https://docs.astral.sh/uv/) reads the Python version and pinned dependencies declared in the script.

Run it directly from this directory:

```sh
./generate_zarr_fixtures.py
```

The string fixtures include valid codec layouts plus deliberately corrupted checksum, truncated-chunk, and invalid-Unicode
variants. The XRADIO fixture exercises the metadata-to-FITS/casacore path and includes coordinate, Stokes, storage, and beam
metadata. Every XRADIO fixture is written as XRADIO image schema 0.0.2, the only schema carta-zarr reads.
zarr-python currently emits its expected unstable-extension warning for fixed-length UTF-32 arrays.

`../images/zarr/xradio/conformance_flagged` is not made here. It is copied unchanged from carta-zarr's
`tests/data/images/zarr/xradio/conformance_flagged` (carta-zarr commit `bc4e3aa`), which carta-zarr's
`tests/data/generate_conformance_fixtures.py` converts with XRADIO 1.2.5 itself, as image schema 0.0.2. Two CASA images, each
with an internal mask over a few known pixels, are converted together as `SKY` and `SKY_OTHER`. The store
holds the flags as XRADIO writes them: each flag an `int8` with `dtype: "bool"`, true where a pixel is bad,
and tied to its image only by the root's `data_groups`.
